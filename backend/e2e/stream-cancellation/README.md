# 流式取消端到端驱动

先阅读仓库根目录 `STREAM_CANCELLATION_RELEASE.md` 中的复现命令与数据库隔离要求。

`main.go` 调用真实配置载入、转发服务和 HTTP 传输。账号与上游均为隔离夹具。它不启动正式的鉴权、账号调度或管理界面。

`check.py` 使用真实 HTTP 连接和本机模拟上游。它检查三个客户端协议、两个上游协议、配置校验、断开时限、部分用量、完整用量、缺失或空用量，以及不可重试冲突。另验证取消与完成竞争、迟到与重复用量，以及共享旧传输策略。OpenAI Responses 透传的既有数据间隔计时器缺口在结果中单独说明。检查结果保存在指定的新目录。失败工件不会覆盖其他运行。

`database.go` 使用正式迁移、用量仓储与结算仓储。数据库名必须是 `stream_cancellation_e2e`。验收需要全新数据库。它使用合成余额和价格，不消耗真实账号额度。

驱动只绑定本机地址。不要将其暴露为生产服务。


CI 在后端单元测试和集成测试后运行本驱动，并上传两个上游协议的检查工件。独立断开时限的回归检查位于真实 HTTP 传输层。解析器不再安装旧的断开后间隔计时器。

支付服务的既有隔离夹具只模拟 `wallet_*` SQL 调用边界，不实现或证明账本余额。CI 另运行 `tools/production-billing-e2e`，以真实服务器、PostgreSQL、Redis 和受控上游验证实际余额、退款与幂等，并上传回执。
