# 用户故事：为现有用户分配 vm2api 专属订阅

状态：需求已确认，待实现和验收。来源：2026-11-19 确认的管理员分配订阅流程。

作为 sub2api 管理员，我希望在为现有用户分配订阅时，一次确认即可开通该用户的专属分组。这样，用户通过该订阅调用 Claude API 时，vm2api 可以用该用户自己的 API Key 识别调用身份。

## 管理员操作

1. 管理员选中一个已有的 sub2api 用户，点击「分配订阅」。
2. 弹窗默认选中「创建专属分组」。管理员也可以切换到「选择已有分组」。
3. 管理员保留默认选项并点击「确认」。sub2api 使用所选用户的用户名在 vm2api 查找同名用户。
4. 如果同名用户不存在，sub2api 在 vm2api 创建该用户。如果同名用户已存在，sub2api 复用该用户，并在用户停用时将其激活。
5. sub2api 获取该 vm2api 用户的 API Key，并用它在 sub2api 创建一个类型为 Claude API 的上游账户。
6. sub2api 为该上游账户创建专属分组，并将上游账户加入该分组。
7. sub2api 将该专属分组的订阅分配给最初选中的 sub2api 用户。

## 用户查看专属分组用量

作为持有专属订阅的用户，我希望看到 vm2api 为该订阅返回的每个槽位的用量，以便分别了解每个槽位在 5 小时和 7 天窗口内已用了多少。sub2api 根据分组类型选择数据来源。新类型使用 vm2api 的槽位用量。普通分组沿用现有的用量和手动限额展示。

## 验收条件

| 场景 | 预期结果 |
|---|---|
| 打开弹窗后取消 | 默认选项为「创建专属分组」。取消后，两端均无新增资源。原有用户的激活状态保持不变。 |
| 确认时，vm2api 没有同名用户 | vm2api 新增一个可调用的同名用户。新上游账户使用该用户的 API Key。 |
| 确认时，vm2api 同名用户已停用 | 原 vm2api 用户恢复激活。新上游账户使用原用户的 API Key。 |
| 确认时，vm2api 同名用户已激活 | 系统复用该用户，并使用其 API Key 创建上游账户。 |
| 专属订阅分配完成 | 所选 sub2api 用户持有新分组的订阅。该分组仅包含为该用户创建的 Claude API 上游账户。 |
| 所选用户通过该订阅发起请求 | sub2api 经专属分组的上游账户转发请求。vm2api 将调用识别为对应的同名用户。 |
| 管理员选择已有分组并确认 | 系统按原流程分配所选分组的订阅。两端均不创建专属资源。 |
| 专属分组有多个槽位 | 用量接口按槽位返回数据。界面为每个槽位分别展示 5 小时和 7 天已用比例。 |
| 某个槽位缺少一个窗口的数据 | 该窗口显示「暂无数据」。其他窗口和槽位仍显示各自的结果。 |
| vm2api 读取失败 | 界面显示用量暂不可用。手动限额不参与专属分组用量展示。 |

本次需求不包含在 sub2api 中设置或控制 vm2api 用量。

实施步骤见[专属订阅执行计划](VM2API_DEDICATED_SUBSCRIPTION_PLAN.md)。
