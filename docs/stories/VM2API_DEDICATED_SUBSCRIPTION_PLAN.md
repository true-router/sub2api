# vm2api 专属订阅执行计划

对应[用户故事](VM2API_DEDICATED_SUBSCRIPTION_USER_STORY.md)。状态为待实施。目标是让管理员一次确认即可为一个现有用户开通专属订阅。用量控制沿用现状。

## 源码基线

2026-11-19 核对了 sub2api 的 `946fe9927` 和 vm2api 的 `0c57afbb9`。实施前重新核对目标分支及已合并的专属订阅改动。

- [分配弹窗](../../frontend/src/views/admin/SubscriptionsView.vue)同时支持单人分配和批量分配。新方式只用于单人分配。
- [订阅处理器](../../backend/internal/handler/admin/subscription_handler.go)的现有单人入口要求提供用户 ID 和分组 ID。它将有效期、备注和管理员身份传给订阅服务。
- [用户模型](../../backend/ent/schema/user.go)允许用户名为空。vm2api 的 `src/lib/admin/panel-users.mjs` 会规范化用户名。
- vm2api 的 `src/lib/admin/panel-routes.mjs` 提供用户列表、创建、激活和密钥操作。创建用户和创建密钥是两个独立操作。读取历史密钥时可能只能得到掩码。

## 实施顺序

1. **先验证身份与凭据契约。** 在隔离环境中使用两个普通用户。用后端管理凭据访问 vm2api。通过 `GET /api/panel/users` 查找规范化后的用户名。若用户名为空、映射到另一名 sub2api 用户或命中管理账号，停止分配。记录远端用户 ID。后续重试按 ID 核对身份。
2. **跑通最小后端链路。** 为单人专属分配增加管理员入口。客户端只提交所选用户 ID、有效期和备注。后端自行读取用户名。如果用户不存在，通过 `POST /api/panel/users` 创建已启用的普通用户，使用随机密码。如果用户已停用，通过 `PATCH /api/panel/users/:id` 仅更新启用状态。创建遇到同名冲突时重新查询。
3. **取得调用凭据。** 按远端用户 ID 核对密钥所有者与 Claude 调用权限。已有适用密钥时，通过 `POST /api/panel/api-keys/:id/reveal` 获取凭据。没有适用密钥时，先在隔离环境验证创建用户所属密钥的参数和路由范围。遇到多个候选或仅有不可读取的旧密钥时，返回可处理的错误。保留已有密钥。仅在服务端传递明文。
4. **创建本地资源并分配。** 复用 sub2api 的账户、分组和订阅服务。创建 Anthropic 平台的 API Key 类型上游账户。将服务地址指向 vm2api 的 Claude 兼容入口。创建可分配订阅的专属分组，仅绑定新账户。沿用已有订阅服务处理有效期、备注和管理员身份。用该用户的 sub2api 调用凭据发送一次 Claude 请求，核对 vm2api 记录的用户 ID。
5. **处理失败、重试和并发。** 按 sub2api 用户 ID 唯一记录专属绑定。在本地事务内提交可一同写入的关联。远端写入超时后先核对结果，再继续未完成步骤。并发确认只能产生一套本地资源。同一次确认重试不能延长有效期。仅在订阅关联成功后返回成功。日志仅保留资源 ID、失败步骤和请求标识。
6. **接入分配弹窗。** 单人模式默认选择「创建专属分组」。选择「已有分组」时显示原分组选择器，沿用原接口。批量分配沿用已有分组流程。取消和切换选项不发起写请求。提交期间禁用确认按钮。失败时保留所选用户并显示失败原因。

## 端到端验收与交付

| 场景 | 可观察结果 |
|---|---|
| 分别选择没有远端用户、远端用户已停用、远端用户已启用的用户 | 三种情况均可获得可用订阅。已有远端用户的 ID 保持一致。 |
| 两名用户各自开通并发起调用 | 每个分组只有自己的上游账户。用两个请求标识核对 vm2api 记录的用户 ID。 |
| 空用户名、规范化后重名、密钥所有者不符 | 管理员看到明确错误。系统不会发放错误订阅。 |
| 双击确认、并发提交、远端超时、本地分配失败后重试 | 最终只有一个专属分组、一个上游账户和一条有效订阅。同一次操作只计算一次有效期。 |
| 打开后取消、切换到已有分组、按原流程批量分配 | 取消时没有写入。旧流程分配指定分组，不调用 vm2api 管理接口。 |
