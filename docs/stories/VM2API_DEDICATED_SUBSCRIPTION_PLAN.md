# vm2api 专属订阅执行计划

对应[用户故事](VM2API_DEDICATED_SUBSCRIPTION_USER_STORY.md)。状态为本地实现。目标是让管理员一次确认即可为一个现有用户开通专属订阅。用量控制沿用现状。

## 实现与配置

sub2api 使用迁移 `270_vm2api_subscription_bindings.sql` 保存本地用户、远端用户、账户和专属分组之间的关联。两端 ID 的绑定只存在于 sub2api。vm2api 使用自己的用户 ID。此流程不写入 vm2api 的外部用户绑定表。

在 sub2api 服务端设置 `VM2API_INTEGRATION_URL` 和 `VM2API_PANEL_TOKEN`。前者是 vm2api 实例根地址。后者是具有管理权限的服务凭据。使用受保护的服务间连接。vm2api 需要 PostgreSQL 用户和槽位管理功能。确认前只读查询普通用户身份，界面仅展示核对所需字段。新建用户时生成随机密码。账号密钥仅在两个后端间传递。

1. 单人分配默认创建专属分组。批量分配和手选分组沿用原接口。弹窗通过 `GET /api/v1/admin/subscriptions/vm-user-preview` 读取身份。新绑定按用户名核对。已有绑定按同一实例的固定用户 ID 核对。
2. `POST /api/v1/admin/subscriptions/assign-vm-user` 在本地用户行锁内复核预览结果。身份发生变化时要求重新核对。vm2api 的管理接口按内部 ID 激活已有用户并返回可用默认 Key。新用户沿用面板创建接口。
3. sub2api 在一次事务内创建 Anthropic API Key 账户、订阅分组、分组成员、绑定和订阅。并发重试复用已创建的资源。跨服务操作中断后重新预览并确认。同名远端账号可能已创建，本地资源只在事务成功时可见。
4. 专属分组的 `subscription_usage_source` 为 `vm2api`。用户订阅及其进度接口使用订阅所有者和远端 ID 读取已分配或拥有的槽位。每项包含槽位 ID 和两个独立的已用比例。普通分组使用本地限额。空列表、读取失败、窗口缺值和零值分别展示。读取用量不会修改限额或触发主动探测。

## 复跑隔离验收

准备 PostgreSQL、Redis、Go、Node.js，以及两个仓库的锁定依赖。在 sub2api 的 `frontend` 目录执行 `pnpm build`。在 `backend` 目录构建嵌入界面的服务，再运行下列命令。传入配套 vm2api 检出的绝对路径。浏览器检查使用本机 ego-browser。

```sh
go build -tags embed -o /tmp/sub2api-vm-test ./cmd/server
python3 e2e/vm-user-subscriptions/check.py --binary /tmp/sub2api-vm-test --vm-repo /path/to/vm2api --pg-bin /path/to/postgresql/bin --output /tmp/vm-user-evidence --browser
```

## 端到端验收与交付

| 场景 | 可观察结果 |
|---|---|
| 分别选择没有远端用户、远端用户已停用、远端用户已启用的用户 | 三种情况均可获得可用订阅。已有远端用户的 ID 保持一致。 |
| 两名用户各自开通并发起调用 | 每个分组只有自己的上游账户。用两个请求标识核对 vm2api 记录的用户 ID。 |
| 空用户名、规范化后重名、密钥所有者不符 | 管理员看到明确错误。系统不会发放错误订阅。 |
| 双击确认、并发提交、远端超时、本地分配失败后重试 | 最终只有一个专属分组、一个上游账户和一条有效订阅。同一次操作只计算一次有效期。 |
| 打开后取消、切换到已有分组、按原流程批量分配 | 取消时没有写入。旧流程分配指定分组，不调用 vm2api 管理接口。 |
| 同一专属分组的槽位 A 返回 12% / 64%，槽位 B 返回 81% / 9% | 核对 vm2api 响应、sub2api 两个用量接口和界面截图。四个数值按槽位及窗口一一对应。 |
| 一个窗口返回 0%，另一个缺失；随后模拟上游失败和空槽位列表 | 分别显示 0%、暂无数据、暂不可用和暂无槽位。其他槽位的有效数值正常展示。 |
| 两个用户具有不同的可见槽位，另有一个普通分组 | 用户只能读取自己订阅的槽位。普通分组仍按本地手动限额展示。 |

验收使用隔离的 sub2api、vm2api 和可控的 Claude 上游。保存复跑命令、两端提交号、脱敏输入、资源数量和请求归属摘要。保存弹窗默认状态、已有分组模式和分配结果的截图。分别记录隔离验收与真实环境验收结果。发布状态以实际发布记录为准。
