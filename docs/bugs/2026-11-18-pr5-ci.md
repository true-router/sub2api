# PR #5 持续集成故障

## 背景与影响

提交 `babbe6ca14801257ca7041e26c45aa564c394c3e` 的分支推送和 PR 检查均失败。前端静态检查报告 26 项错误，Go 静态检查报告一处错误。协议矩阵有 4816 项与既有基准不一致。macOS 作业未取得运行机。[原始 CI](https://github.com/true-router/sub2api/actions/runs/44296815253)

## 根因与证据

浏览器验收脚本由宿主注入 `taskSpace`，ESLint 未声明这个全局变量。二维码脚本还直接引用了浏览器提供的 `BarcodeDetector`。预览轮询存在空异常处理块和多余分号。OpenCode OAuth 客户端忽略只读响应体的关闭返回值。OpenCode OAuth 接入还把两个原生 Anthropic 转发入口从协议专用凭证读取改成了通用令牌读取。它改变了其他账号类型的认证行为。macOS 作业没有执行步骤。GitHub 注释说明 ARM 运行机容量不足。

## 修复方式

在浏览器脚本范围声明宿主全局变量。通过 window 使用浏览器检测器。明确轮询期间允许连接尚未建立。按仓库约定关闭只读响应体。恢复两个入口的协议专用凭证读取。该读取方法已有 OpenCode OAuth 支持，入口仍负责刷新账号。部署脚本使用模拟容器命令，切换到 macOS 15 的 Intel 运行机。修复位于 true-router/sub2api 的 feat/user-recharge-filter 分支。[PR #5](https://github.com/true-router/sub2api/pull/5)

## 验证结果

本地运行既有路由矩阵，固定基准通过。原有基准和例外均保持原样。本地 Apple 容器生命周期、Compose 安全、网关环境、运行资源和 Caddy 配置检查通过。复验命令为 backend 目录下的 `go test -tags unit ./internal/service -run '^TestUpstreamProtocolRoutingMatrixMatchesMainGolden$' -count=1` 及仓库根目录的 `make test-frontend`。GitHub 会针对分支推送和 PR 合并结果分别执行完整检查。[远端检查](https://github.com/true-router/sub2api/pull/5/checks)

## 发布与收尾

未发布或部署。保留原功能工作树交付修复。可通过还原修复提交撤销代码变更。
